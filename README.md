# 🩺 呼吸道周报 · 本周流行什么

> 把中国疾控中心每周的呼吸道传染病监测、流感周报和每月法定传染病报告，翻译成一页看得懂的「本周流行什么」

**🌐 在线访问：[https://climb0516.github.io/health-weekly/](https://climb0516.github.io/health-weekly/)**

---

## 功能

- **一句话结论**：本周门诊头号病原体、阳性率及较上周变化；南方 / 北方流感处于低 / 中 / 高流行水平（引用官方原话）
- **要点四格**：流感样病例占门诊比例（南北方）、流感阳性率、新冠阳性率、流感样病例暴发起数
- **病原体排行**：门急诊和住院两组，11 种病原体（新冠、流感、合胞病毒、腺病毒、人偏肺、副流感、普通冠状、博卡、鼻病毒、肠道病毒、肺炎支原体）阳性率横条，标出较上周升降
- **近一年走势**：可切换病原体或流感样病例比例，每周一个点，悬停看数值；一眼看出流感季是否来了
- **谁更容易中招**：南北方各自排名前三的病原体
- **官方分析与健康提示**：原文摘录，不自行编写医疗建议
- **每月法定传染病**：流感、手足口、感染性腹泻（含诺如）、水痘、猩红热、新冠的近两年月度小走势，以及当月发病数前十和环比
- 右侧：流感监测周报（甲 / 乙型、H3N2 / H1N1 占比与概要）、更新节奏、来源状态
- 深色 / 浅色主题，手机适配

数据仅供了解流行趋势，不构成医疗建议；身体不适请及时就医。

## 技术架构

```
GitHub Actions（触发：每天 10:05 北京时间 / 手动 dispatch / push 修改 scraper.py 或 workflow）
  ↓ python scraper.py（Python 3.12，只用标准库）
  ↓ 抓中国疾控中心三个栏目：列表页 → 详情页 → 正则解析正文和表格
  ↓ 已解析过的期次按 URL 缓存在 data.json，不重复请求；首次运行补抓近 60 周 / 30 期 / 36 个月
  ↓ 写入 data.json（updated 每次都变 = 心跳）→ git commit → push
       ↓
GitHub Pages（index.html，fetch('data.json') 后纯前端渲染）
  ↓ 首页：结论、要点四格、病原体排行、近一年走势、每月法定传染病
  ↓ kit 详情抽屉（#/item/<类型>/<id>）+ 列表页（#/list/<key>）
```

## 数据来源

全部来自中国疾病预防控制中心官网（`https://www.chinacdc.cn/jksj`），均为**网页解析**（正文和 HTML 表格转纯文本后用正则提取），没有接口 / RSS / PDF 解析。

| 来源 | 方式 | 每次条数 / 范围 | 备注 |
|---|---|---|---|
| [全国急性呼吸道传染病哨点监测情况](https://www.chinacdc.cn/jksj/jksj04_14275/)（每周，周四前后） | 网页解析 | 列表页翻 5 页，标题含「哨点监测」的期次；保留最近 60 周 | 流感样病例百分比（全国 / 南方 / 北方）、表 1 各病原体阳性率及较上周、表 2 南北方前三、分析与健康提示 |
| [流感监测周报](https://www.chinacdc.cn/jksj/jksj04_14249/)（每周） | 网页解析 | 列表页翻 3 页，标题含「流感监测周报」的前 30 期；保留最近 30 期 | 只取网页文字概要（甲 / 乙型、H1N1 / H3N2 占比、暴发起数）；具体阳性率在 PDF 附件里，不解析 |
| [全国法定传染病疫情情况](https://www.chinacdc.cn/jksj/jksj01/)（每月，中旬发布上上月） | 网页解析 | 列表页翻 3 页，标题含「疫情概况」的月份；保留最近 36 个月 | 统计表中各病种发病数、死亡数，以及全国合计 |

**配置位置**：`scraper.py` 顶部常量
- `CDC`：栏目根地址；`ARI` / `FLU` / `MONTHLY`：三个栏目的目录名
- `PATHOGENS`：表 1 要解析的 11 种病原体名（必须和官方表格写法一致）
- `MAX_WEEKS, MAX_MONTHS, MAX_FLU = 60, 36, 30`：各自保留的期数
- 列表页翻几页写在各函数里：`ari()` 是 `list_page(ARI, 5)`，`flu()` / `monthly()` 是 3 页

**增删来源**：新写一个 `parse_xxx(url, title, text)` + `xxx(old)`（参照 `monthly()`：读列表页 → 按标题关键词过滤 → URL 命中缓存直接复用 → 否则抓详情页解析），然后在 `main()` 里用 `run("显示名", xxx)` 调用并把结果放进 `data`；删除来源就去掉对应的 `run(...)` 行，前端同步删掉渲染。

**限制**：
- 2026 年 4 月以前的哨点报告没有表 1，只在正文写前三位病原体，所以走势图早期只有上榜的病原体有点
- 报告格式改版时解析会失败，页面沿用上一次的数据并在来源状态里标出

## 数据处理规则

**通用**
- `fetch()`：带桌面 Chrome UA，超时 20 秒，UTF-8 解码
- `text_of()`：去掉 `<script>` / `<style>` 和全部标签，合并空白；把老报告里「（ 10.5% ）」这类括号、百分号两侧的空格去掉，方便正则匹配
- `list_page(section, pages)`：第 1 页是 `<栏目>/`，之后是 `index_1.html`、`index_2.html`…；用正则 `href="./YYYYMM/t…_….html"` 取详情链接和标题，某页请求失败就停止翻页
- 新期次之间 `time.sleep(0.3)`，补历史时放慢请求

**哨点监测 `parse_ari()` / `ari()`**
- 周次：从标题或正文匹配「2026年第41周」；日期区间匹配「第N周（2026年10月5日—10月11日）」，跨年时第二个年份可省略
- 流感样病例百分比：「流感样病例百分比）为 X%」，南北方匹配「南方省份（X%）」「北方省份（X%）」
- 表 1：定位到「表1 第N周」标题，截到「注：」为止；每种病原体先按「名称 门急诊% 较上周 住院% 较上周」四个数匹配，不行再按老格式「名称 门急诊% 住院%」两个数匹配（`chg` 记为 null）
- 兜底：没有表 1 时，从正文「门急诊流感样病例……前三位病原体为X（a%）、Y（b%）…」「住院严重急性呼吸道感染病例……」取前三
- 表 2：定位「表2 第N周」，按「南方省份 … 北方省份 … 南方省份包括」切出两段，空格分词后前 3 个是门急诊、第 4–6 个是住院
- 分析与健康提示：取「二、分析及健康提示」之后到「表1」（没有就取 1500 字），「为防范」之前是分析正文，「（1）…（2）…」拆成提示，最多 6 条
- 流行水平：在分析正文里匹配「南方省份……处于(低|中|高|较…)流行水平」
- 去重：新旧结果按 URL 合并，按 (年, 周) 倒序，同一周有更正版时只保留一条，截取前 60 周

**流感周报 `parse_flu()` / `flu()`**
- 截至日期：「概要（截至2026年10月11日）」→ `until`
- 概要：「概要」到「文件附件」（没有就取 2000 字），按「·」分条，第 1 条为 `summary`，第 2–3 条（各截 400 字）为 `more`（抗原性 / 耐药性等）
- 占比：「甲型流感病毒占比X%、乙型流感病毒占比Y%」「A(H1N1)pdm09占比X%、A(H3N2)占比Y%」
- 暴发：「共报告N起流感样病例暴发疫情」；正文写「未报告流感样病例暴发」时记 0，都没有记 null
- 按 URL 合并缓存，按 `until` 倒序，保留 30 期；兼容旧版只有单个 `flu` 字段的 data.json

**法定传染病 `parse_month()` / `monthly()`**
- 月份取自标题「2026年8月」；合计匹配「全国共报告法定传染病N例，死亡M人」
- 「统计表」之后逐行匹配「病名 [1~2 位脚注] 发病数 死亡数」，跳过表头（病名 / 发病数 / 死亡数）和重复病名
- 解析不出病种的月份丢弃；按月份倒序保留 36 个月

**容错 `main()` 里的 `run()`**
- 每个来源单独 try：成功记 `ok: true, count`；失败记 `ok: false, error`（截 120 字），并沿用上次的数据和上次成功的 `updated`

**前端计算（index.html）**
- 首页结论：本周门急诊阳性率最高的病原体及其「较上周」百分点
- 法定传染病环比 = 本月 / 上月 − 1；病种详情另算同比（去年同月）、当年累计、近 N 个月最高
- 首页「发病数前十」去掉甲 / 乙 / 丙 / 丁 / 戊型和未分型肝炎子类（已含在「病毒性肝炎」里），列表页全部列出
- 首页关注病种 `WATCH`：流行性感冒、手足口病、其他感染性腹泻病、水痘、猩红热、新型冠状病毒感染，画近 24 个月小走势

## 数据结构

所有数据都在一个 `data.json` 里（没有其他 json 或快照文件）。

```
{
  "updated": "2026-10-22T12:48:30+08:00",   // 北京时间，每次运行都变（心跳）
  "weeks": [ {                               // 新的在前，最多 60 周
    "year": 2026, "week": 41, "period": ["2026-10-05", "2026-10-11"], "url": "...",
    "ili": 3.8, "ili_south": 4.6, "ili_north": 3.0,
    "outpatient": { "流感病毒": { "rate": 13.6, "chg": 2.4 }, ... },   // 门急诊阳性率 %，chg 为较上周百分点（老报告为 null）
    "inpatient":  { ... },                                            // 住院，结构同上
    "region": { "south": { "out": [前三], "in": [前三] }, "north": {...} },
    "level": { "south": "中流行水平", "north": "低流行水平" },
    "analysis": "官方分析原文", "tips": ["…", ...]                   // tips 最多 6 条
  } ],
  "flu":  { 同 flus[0] },                    // 最新一期流感周报（兼容旧前端）
  "flus": [ {                                // 按 until 倒序，最多 30 期
    "title", "url", "until": "2026-10-11", "summary",
    "a_pct", "b_pct", "h1n1_pct", "h3n2_pct", "outbreaks",
    "more": ["抗原性 / 耐药性等要点", ...]
  } ],
  "months": [ {                              // 新的在前，最多 36 个月
    "month": "2026-08", "url", "total", "deaths",
    "diseases": { "流行性感冒": [发病, 死亡], ... }
  } ],
  "sources": [ { "name", "ok", "count", "updated", "error?" } ]   // 三个来源的抓取状态
}
```

## 前端

单页 `index.html`，原生 JS，无构建；`fetch('data.json', { cache: 'no-cache' })` 读取数据，右上角刷新按钮重新读取。

**kit 详情抽屉 + 列表页**（内联在页面里的通用组件 `KIT`）
- 点击条目打开详情抽屉：电脑端从右侧滑出，手机端（≤ 760px）从底部升起；`Esc`、点遮罩或浏览器返回关闭
- 详情地址 `#/item/<类型>/<id>`，列表页地址 `#/list/<key>`，都写进地址栏，分享链接可直接打开（数据加载完后 `KIT.boot()` 弹出详情）
- 链接里的条目在当前数据中找不到（已下榜 / 过期 / 旧链接）时，弹出「这条内容已不在当前数据里」提示，并给「回到首页」按钮

本项目的条目类型：

| 类型 | id | 内容 |
|---|---|---|
| `pathogen` | 病原体英文短码：`covid` `flu` `rsv` `adv` `hmpv` `piv` `hcov` `hbov` `rv` `ev` `mp`，以及 `ili`（流感样病例百分比）；也兼容中文名 | 本周阳性率、门急诊 / 住院近 60 周走势、最近 8 周变化、南北方前三出现次数、其它病原体 |
| `week` | `<年>-<周>`，如 `2026-41` | 一期哨点监测：关键数字、门急诊阳性率、南北方前三、官方分析、健康提示、前后几期 |
| `flu` | 流感周报截至日期 `until`（缺失时用 URL 里的编号） | 甲 / 乙型及亚型占比、概要、毒株分析、近 30 期暴发疫情走势 |
| `disease` | 病种中文名（URL 编码） | 本月发病 / 死亡、环比、同比、当年累计、近 36 个月发病和死亡走势、最近 12 个月表格 |

本项目的列表页：

| key | 内容 | 参数 |
|---|---|---|
| `weeks` | 往期哨点周报 | `?year=2026` 按年份筛选 |
| `flu` | 中国流感监测周报 | — |
| `diseases` | 当月全部法定传染病 | `?sort=cases / deaths / chg / name`（发病数 / 死亡数 / 环比 / 名称） |

列表页每页 30 条，「加载更多」追加 30 条。

**项目特有功能**
- 近一年走势：可切换病原体或流感样病例比例，SVG 折线图，悬停看数值；选择记在 `localStorage`（键前缀 `hw:`）
- 顶部导航锚点（病原体 / 走势 / … ），在列表页点导航会先回首页再滚到对应位置
- 深色 / 浅色主题切换，记在 `localStorage`，默认深色
- 窗口宽度变化时重画走势图；手机端导航横向滑动

## 本地运行

```
python3 scraper.py      # 首次会补抓历史，约 1–2 分钟；之后只抓新期次
python3 -m http.server 8795
# 打开 http://localhost:8795
```

- 依赖：Python 3（CI 用 3.12），只用标准库，无需 `pip install`
- 环境变量：无，不需要任何密钥
- 页面必须通过 HTTP 服务打开（直接双击 index.html 时 `fetch` 读不到 data.json）

## 自动更新机制

| 触发方式 | 时机 |
|---|---|
| GitHub Actions 定时任务（cron `5 2 * * *`） | 每天 10:05 北京时间（周报一般周四前后发布，每天检查一次） |
| push 到 main 分支 | 仅当改动了 `scraper.py` 或 `.github/workflows/scrape.yml` |
| GitHub Actions 手动 dispatch | 按需触发 |

- workflow：`.github/workflows/scrape.yml`，`concurrency: scrape`（不取消进行中的任务），权限 `contents: write`
- 运行完执行 `git add data.json`，有变化才提交（提交信息 `data: update <北京时间>`），然后 `git pull --rebase` 再 push
- **心跳**：data.json 里的 `updated` 每次运行都会变，所以即使官方没有新报告，每次运行也都有提交，仓库保持活跃
- GitHub 规定：仓库 60 天没有提交会自动停用定时任务；有了上面的心跳一般不会触发，若被停用需到 Actions 页面手动重新启用
